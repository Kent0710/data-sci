# Project Writing and Documentation Rules

This project follows specific documentation and writing standards for all project deliverables, notebook markdown, and reports.

## Core Writing Rules

1. **Third-Person Perspective:**
   - Write strictly in third-person (e.g., "the researchers", "the analysis", "the team", "the model").
   - Never use first-person pronouns such as "I", "we", "our", or "us".

2. **ASD-STE100 Principles (Simplified Technical English):**
   - Use simple, straightforward words; avoid complex jargon or flowery language.
   - Keep sentence structures short and simple (maximum of approximately 20 words per sentence).
   - Express one clear idea per sentence.
   - Keep the tone casual, direct, and conversational while maintaining professional accuracy.

3. **Format & Layout:**
   - Output must be in cohesive paragraph format.
   - Output must be in plain text without code markdown or backticks (e.g., write `df.shape` as `df.shape`, not enclosed in backticks).
   - For outputs accompanying figures/tables:
     - **Content Above:** State what function or operation was run, why it was run, its purpose, and introduce the result.
     - **Content Below:** Discuss and interpret the results, figures, statistics, or metrics.

4. **Project Requirements Context:**
   - Institution: De La Salle Lipa (DLSL) - Computer Science Department.
   - Course: Introduction to Data Science (Intdsci).
   - Task: Supervised machine learning predicting student depression (binary classification: 0 = Not Depressed, 1 = Depressed).
   - Evaluation metrics: Confusion Matrix, Accuracy, Precision, Sensitivity (Recall), and F1-Score.
